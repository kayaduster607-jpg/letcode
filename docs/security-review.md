## 与潜在密钥泄漏有关的修复

### 视频资源服务的公开边界

原资源接口按相对路径读取文件，没有限制隐藏配置文件或资源类型。如果演示目录中放入配置文件，存在被接口返回的风险。本次没有读取配置来验证，而是在文件访问前增加了路径策略：

1. 只接受合法题目 slug 和 `presentation/` 内的路径。
2. 拒绝隐藏文件、路径分隔注入、上级目录和密钥文件类型。
3. 拒绝常见凭据、配置和 token 文件名。
4. 检查真实路径，拒绝越界符号链接及指向隐藏配置的链接。
5. 仅按明确的公开资源 MIME 类型返回内容。

30 项边界测试通过。相关 HTTP 请求仅使用路径字符串验证拒绝行为，未创建或打开任何 env 文件。

### 可选语音脚本

`scripts/synthesize_hot100_mimo.py` 改为仅从调用进程的 `MIMO_API_KEY` 环境变量读取密钥，移除了隐式读取其他桌面项目 env 文件的逻辑。输出和日志默认位置也改为当前项目目录。

主应用与动画页面生成不需要 API Key。本次没有运行语音合成，没有向模型服务发送任何凭据。

### 运行数据与构建产物分离

账号数据可通过 `HOT100_DATA_DIR` 指向独立目录。文件追踪明确排除了运行时私有数据和外部生成资源，避免把动态数据作为 standalone 服务源码打包；Docker 使用数据卷保存账号文件，演示资源在构建阶段单独生成。

## 依赖安全检查

原锁文件的 npm 审计存在严重及其他已知漏洞命中。本次在 Next.js 16 主版本内更新至 16.4.1，并按官方修复版本固定 PostCSS、sharp 等传递依赖。最终 `pnpm audit` 返回 **0 条已知漏洞告警**。

修复版本依据包括 Next.js 的 [图像优化安全公告](https://github.com/advisories/GHSA-2464-fhr4-w9xw) 与 [use cache 安全公告](https://github.com/advisories/GHSA-673q-mjm6-r5xr)，同时核对了 npm registry 中版本及 Node.js 要求。更新后重新完成生产构建和 HTTP 验证。

审计结果与当时的锁文件及漏洞库有关，不代表系统不存在其他漏洞。账号默认密码、单实例 JSON 存储及部署边界见 README。
