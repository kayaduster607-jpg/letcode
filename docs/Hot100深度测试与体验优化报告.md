## 2. 本轮发现并修复的问题

### 2.1 生产构建卡住 / 部署不可控

**问题：** 动态题目详情页 `/problem/[slug]` 在生产构建的页面数据收集阶段存在卡住风险。

**修复：**

- 将题目详情页拆成 Server Component + Client Component。
- 在 `src/app/problem/[slug]/page.tsx` 增加 `generateStaticParams()`。
- 100 道题目页现在会在构建时静态生成。
- 增加每道题的动态 metadata，标题和描述更适合分享与 SEO。

### 2.2 题目 33「搜索旋转排序数组」讲解方向错误

**问题：** 原内容把本题讲成了「寻找旋转数组最小值」，与 LeetCode 33 的目标值搜索不一致。

**修复：**

- 重写 summary、learningGoal、whyThisPattern。
- 重写分层提示与暴力/优化思路。
- 修正复杂度解释和常见错误。
- 保证新手学习时能明确掌握「先判断哪一边有序，再判断 target 是否落在有序区间」。

### 2.3 题目 154「寻找旋转排序数组中的最小值 II」描述不严谨

**问题：** 题目含重复元素，但原文出现了类似「互不相同」的表达，容易误导学生。

**修复：**

- 修正题目摘要和学习目标。
- 强调 `nums[mid] == nums[right]` 时只能安全收缩 `right -= 1`。
- 明确说明最坏情况会退化为 `O(n)`。

### 2.4 前缀树题型被误归入图论

**问题：** LeetCode 208「实现 Trie」原来按图论泛化讲解，教学焦点不准确。

**修复：**

- 新增 `前缀树` 分类图标与方法论。
- 重写 Trie 的手撕步骤、常见坑和面试检查单。
- 明确 `search` 与 `startsWith` 的区别：前者必须检查 `is_end`，后者只需要路径存在。

### 2.5 单调队列 / 前缀和题目分类不够清晰

**问题：** 「滑动窗口最大值」和「和为 K 的子数组」放在泛化的子串模块下，小白容易以为都能套普通滑动窗口。

**修复：**

- LeetCode 239 调整为 `单调队列`。
- LeetCode 560 调整为 `前缀和`。
- 学习路线中的「子串」模块升级为「窗口、单调队列与前缀和」。
- 新增 `单调队列` 与 `前缀和` 的方法论卡片。

### 2.6 提示解锁存在“回退上锁”风险

**问题：** 用户已经解锁到后面步骤后，再点前面的步骤，有机会把已解锁层级写回较低值。

**修复：**

- `GuidedStepCard` 中解锁层级改为只增不减。
- 避免学习过程中的答案和代码突然重新锁住。

### 2.7 笔记存在最后 500ms 输入丢失风险

**问题：** 笔记使用防抖保存，如果用户刚输入完就切换页面，最后一小段内容可能还没写入 localStorage。

**修复：**

- `useNotes` 增加 pending 缓冲与卸载前 flush。
- `NoteEditor` 增加 `onBlur` 立即保存。
- 用户离开文本框或切换题目前，最后一次输入会被尽量保存。

### 2.8 localStorage 脏数据会污染学习进度

**问题：** 如果浏览器里残留旧 id、重复 id、非法 hint level、异常错题记录，进度和错题本统计可能异常。

**修复：**

- `src/lib/storage.ts` 增加统一清洗逻辑。
- 只保留当前 100 道题的合法 id。
- completed、wrongBook、notes、unlockedHints 全部做去重、过滤和范围限制。
- 错题记录中的无效日期、空 reason、非法 problemId 都会被修正或过滤。

### 2.9 错题本“待复盘”逻辑过粗

**问题：** 原来错题本只按是否掌握分类，缺少复盘节奏。

**修复：**

- 新增 3 天复盘间隔。
- 「待复盘」只展示未掌握且到期的题目。
- 空状态文案更明确，告诉用户如何添加错题和如何标记掌握。

### 2.10 依赖安全告警

**问题：** 初次检查发现 `postcss` 链路存在 moderate 级安全告警。

**修复：**

- 在 `package.json` 增加 `overrides`，锁定安全版本链路。
- 重新安装依赖后，`npm audit` 结果为 0 vulnerabilities。

## 3. 新增测试脚本

新增：

```bash
npm run qa:content
npm run verify
```

其中：

```bash
npm run qa:content
```

会检查：

- 是否正好 100 道题。
- 100 道题是否都有精修内容。
- id、leetcodeId、slug 是否重复。
- 学习路线是否完整覆盖 100 题。
- externalUrl 是否与 slug 对齐。
- summary、learningGoal、whyThisPattern、bruteForceIdea、optimizedIdea、pseudocode、solutionCode 是否过短或为空。
- 常见错误是否至少 3 条。
- 复盘问题是否至少 4 条。
- 时间/空间复杂度是否完整。
- Python 代码片段是否能通过 AST 语法解析。
- 边界样例是否至少 3 个，并包含 input、expected、why。
- 面试手撕步骤和检查单是否完整。

```bash
npm run verify
```

会串联执行：

```bash
npm run lint
npm run qa:content
npm audit --audit-level=moderate
npm run build
```

## 6. 继续迭代建议

当前已经完成了数据、构建、路由、内容、状态和安全层面的基础 QA。后续如果继续产品化，优先级最高的方向是：

1. 增加题目详情页的运行样例模拟器，让用户能输入样例并观察关键变量变化。
2. 增加「今天学什么」和「遗忘曲线复习」视图，把错题本升级成复习系统。
3. 为每个题型增加 3～5 道迁移练习，避免学生只会背 Hot100 原题。
4. 增加前端自动化测试框架，例如 Playwright，覆盖解锁、收藏、笔记、错题本等交互链路。
